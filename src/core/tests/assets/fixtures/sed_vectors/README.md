# SED V1 conformance vectors

These files are checked-in byte-level goldens for the legacy texture-pixel SED V1
wire format. They remain a deliberately stable corpus for import, recovery, and
text-export parity. Tests must read these files; they must not derive the expected
bytes from the writer under test during an ordinary test run. Focused core tests
also cover normalized V2/V3 and MotS arch-lighting V3/V4 behavior; those newer
profiles do not replace this V1 golden corpus.

## Project conversion matrix

Each project has five related vectors:

| Project | Legacy input | Native document | Expected normal export | Unrecoverable native document | Expected partial export |
|---|---|---|---|---|---|
| JKDF2 | `jkdf2_input.jkl` | `jkdf2_native.sed` | `jkdf2_expected.jkl` | `jkdf2_sect_unrecoverable.sed` | `jkdf2_expected_partial.jkl` |
| MotS | `mots_input.jkl` | `mots_native.sed` | `mots_expected.jkl` | `mots_sect_unrecoverable.sed` | `mots_expected_partial.jkl` |
| IJIM | `ijim_input.ndy` | `ijim_native.sed` | `ijim_expected.ndy` | `ijim_sect_unrecoverable.sed` | `ijim_expected_partial.ndy` |

Each project input must retain exactly one Sector, three vertices, and one three-corner Surface on import; the
geometry assertion prevents a malformed fixture from passing through equally empty native and text outputs. The
IJIM input omits COLORMAPS and uses version-3 RGB Surface/Sector fields. An empty classic COLORMAPS section or
scalar version-3 colour fields are invalid fixture input. Its expected normal export retains that triangle.

The IJIM parity input explicitly contains `TINT 1 1 1`, matching the authored
white tint retained by its checked-in native and expected-export vectors. The
separate JKL asset tests cover an omitted IJIM `TINT` record: import defaults
its engine tint to all-zero RGB and export does not synthesize a record.

The normal conversion assertion is:

```text
legacy input --import--> Level --SED V1 writer--> generated bytes
                                             |           |
                                             |           +-- must equal *_native.sed
                                             v
                                      open *_native.sed
                                             |
                                             v
                                  canonical JKL/NDY export
                                             |
                                             +-- must equal *_expected.{jkl,ndy}
```

The corruption/salvage assertion is:

```text
*_native.sed
     |
     +-- damage five independently CRC-checked sect slots in one stripe
     v
generated damaged bytes == *_sect_unrecoverable.sed
     |
     +-- native recovery (p=4 cannot repair five erasures)
     v
whole sect domain reported lost; independently checked domains retained
     |
     +-- bounded project-native text salvage
     v
exact bytes == *_expected_partial.{jkl,ndy}
```

Four damaged slots are also tested dynamically and must reconstruct the
complete Level and the normal expected export exactly. Five slots deliberately
exceed the required-Level `p=4` budget; no record-level guessing is allowed.

## Categorized-resource vector

`all_resource_categories.sed` contains all 14 fixed V1 catalogs and references
them from the applicable Level structures. Coverage includes:

```text
rsrc[0]  names          <- unknown values, parameter names, descriptions,
                           Thing instance names, hierarchy-node names
rsrc[1]  colormaps      <- head.masterCMP, Sector.colormap, inventory
rsrc[2]  materials      <- Surface.material, MAT parameters, inventory
rsrc[3]  sounds         <- Sector.sound, WAV COG parameters
rsrc[4]  aiClasses      <- Thing/template and COG parameters
rsrc[5]  models3do      <- Thing/template and COG parameters
rsrc[6]  sprites        <- Thing/template parameters
rsrc[7]  keyframes      <- COG parameters
rsrc[8]  puppets        <- Thing/template parameters
rsrc[9]  soundClasses   <- Thing/template parameters
rsrc[10] cogScripts     <- Cog.name and typed parameters
rsrc[11] templates      <- Thing.templateName, template name/parent,
                           typed parameters
rsrc[12] particles      <- Thing/template parameters
rsrc[13] layers         <- ordered layer inventory
```

Every category has its own zero-based index space. Fixed-schema fields encode
only a `sedIndex`; the field or preceding `AdjType`/`CogType` supplies the
category. Tests verify exact catalog order, exact category-local references,
the `-1` empty sentinel, one-byte small-index encoding, deterministic protected
file bytes, strict opening, and complete semantic equality.

Checked-in native vectors use the canonical unknown document timestamp
`timestamp = 0`, so they remain byte-deterministic; production Save and
recovery supply a real creation time through the same codec.

The three native project vectors also assert the complete canonical stability
contract: importing the legacy fixture and writing SED must match the checked-in
bytes, and opening that checked-in SED followed by another canonical V1 write
must produce the same bytes. This is intentionally tested with timestamp zero;
runtime timestamps are fixed-header metadata and are not part of this golden
contract.

The test also traverses this Level independently of the production resource
indexer. Its 91 occurrences contain 54 unique nonempty strings. The affected
wire fields require 1,366 bytes with repeated inline strings, 1,304 bytes with
categorized catalogs plus fixed `u32` references, and 1,031 bytes with the
actual catalogs plus ULEB128 references: a 335-byte (24.52%) total reduction.
The compact references occupy 91 instead of 364 bytes (75% less). Collection
counts common to all representations are excluded; protected-file size can be
rounded by the 4 KiB FEC-slot layout.

## Recovery/autosave coverage

`.sedrecovery` is not a second Level format. Production autosave and crash
recovery both call the same `writeRecoverySnapshot` path, which stores one raw
native SED document in `docm`. Application tests load each checked-in native
project vector into that path, reopen the resulting `.sedrecovery`, and compare
its exported JKL/NDY with the checked-in expected text. They then destroy the
enclosed `sect` beyond parity and compare the recovered text with the checked-in
partial vector. The categorized-resource vector is also round-tripped through
the same autosave/recovery path.

The outer `.sedrecovery` bytes are intentionally generated during the test
rather than checked in: capture time, session/source identity, and bindings are
envelope inputs. The authoritative `docm` semantics and resulting exports are
fixed by the checked-in vectors above.

## HIST p=2 golden

`hist_small.sed` is a small IJIM project containing a real `hist` optional
section. Its payload is a canonical `HistoryNested` SED stream, while the
outer optional section uses the V1 p=2 FEC tier. The following checked-in
variants damage the same data-stream positions in every independent stripe:

| File | Damage | Required result |
|---|---:|---|
| `hist_small_1_damage.sed` | 1 chunk per stripe | Strict load repairs HIST exactly |
| `hist_small_2_damage.sed` | 2 chunks per stripe | Strict load repairs HIST exactly |
| `hist_small_3_damage.sed` | 3 chunks per stripe | Strict load rejects; permissive recovery drops only HIST |

The one- and two-chunk cases compare the recovered optional payload byte for
byte with `hist_small.sed`. The three-chunk case verifies that all required
Level sections remain intact and only `hist` appears in the missing-optional
set. These are opaque-core fixtures for the FEC boundary; application-level
history schema tests additionally validate the CBOR/editor-history payload.

## External algorithm vectors

The native codec's hash and checksum seams are checked against applicable
standards in `sed_level_tests.cpp`:

- SHA-256 tests 1, 2, 3, 4, 6, 8, and 10 from
  [RFC 6234 section 8.5](https://www.rfc-editor.org/rfc/rfc6234#section-8.5)
  cover every byte-aligned SHA-256 vector in the RFC test table
- CRC32C vectors from RFC 3720 Appendix B.4 cover four 32-byte patterns and
  the 48-byte iSCSI Read(10) PDU, through both the portable and
  runtime-dispatched implementations

RFC 6234 tests 5, 7, and 9 end on a partial bit and do not apply to SED's
byte-span SHA-256 API. All seven byte-aligned vectors are covered. The
empty-message and 55/56-byte SHA-256 cases in the suite are local digest and
padding-boundary checks, not RFC 6234 table vectors. These algorithm literals
are intentionally kept in source rather than stored as binary SED-format
fixtures.

## Regeneration

Regenerate only for a deliberate, reviewed fixture correction or a changed and deliberately versioned V1 wire contract:

```text
build\ninja\src\core\Release\sed_core_tests.exe --write-sed-vectors
```

For an IJIM-only fixture correction, use the narrower command:

```text
build\ninja\src\core\Release\sed_core_tests.exe --write-sed-ijim-vector
```

It reads `ijim_input.ndy`, verifies the one-Sector triangle, and rewrites only `ijim_native.sed`,
`ijim_sect_unrecoverable.sed`, `ijim_expected.ndy`, and `ijim_expected_partial.ndy`. It does not rewrite the input,
JKDF2/MotS vectors, categorized-resource vector, or HIST vectors. A fixture correction does not itself change the wire
format version.

After regeneration, inspect the binary/text diffs, update the owning fixture/format
documentation, and run all Release suites. Ordinary tests never rewrite these
files.
